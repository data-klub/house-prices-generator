# AWS access for Data Klub members

How team members get their own login to the club's AWS account (`data-klub-lab`, region
`eu-central-1`) to build Lambdas and load files to Databricks, without anyone sharing a password
or an access key.

## Why IAM users, not IAM Identity Center

IAM Identity Center (single sign-on) is the usual choice in companies, but giving it access to an
AWS account needs AWS Organizations, and enrolling a **Free plan** account in Organizations upgrades
it to the Paid plan and ends its Free Tier credits. A small group doesn't need it. So each member
gets an IAM user in one group, with MFA required and a policy that only allows what the club uses.

## What a member can do

| Can | Can't |
|---|---|
| Create, change, run and delete Lambda functions named `dk-*` in Frankfurt | Touch any other function, region or service |
| Give their Lambdas the shared role `data-klub-team-lambda` (and no other role) | Create roles or change anyone's permissions |
| Read their Lambdas' logs and metrics | See billing |
| Read `raw/` and `team/` in the bucket; write and delete only in `team/<their user name>/` | Write to `raw/` or to someone else's folder |
| Keep their own settings (Databricks host and token) in Parameter Store under `/data-klub/<their user name>/` | Read anyone else's parameters |
| Use AWS CloudShell, a terminal in the browser with the AWS CLI already signed in | Do anything at all before setting up MFA |

Name your functions `dk-<your user name>-<what>`, for example `dk-lukasz-hello`.

## Files

| File | What it is |
|---|---|
| `self-service-mfa.json` | Lets members change their password and set up MFA, and blocks everything else until MFA is on (from the AWS IAM user guide example) |
| `team-sandbox.json` | What members can do, as in the table above |
| `lambda-role-trust.json` | Lets the Lambda service use the shared role |
| `lambda-role-policy.json` | What the members' Lambdas can do: write their logs, read `raw/`, write `team/`, read `/data-klub/` parameters |

Replace `<account-id>` and `<bucket>` before pasting a file into the console.

## Setup (an admin does this once, in the console)

1. **Sign-in alias:** IAM → Dashboard → AWS account → **Account alias** → `data-klub-lab`.
   Members then sign in at `https://data-klub-lab.signin.aws.amazon.com/console`.
2. **Password policy:** IAM → Account settings → Password policy: minimum 12 characters.
3. **Shared Lambda role:** IAM → Roles → Create role → **Custom trust policy** (paste
   `lambda-role-trust.json`) → no permissions → name `data-klub-team-lambda`. Then on the role:
   Add permissions → Create inline policy → paste `lambda-role-policy.json` → name it
   `data-klub-team-lambda`.
4. **Two policies:** IAM → Policies → Create policy → JSON, once for each file:
   `self-service-mfa.json` as `data-klub-self-service-mfa`, and `team-sandbox.json` as
   `data-klub-team-sandbox`.
5. **Group:** IAM → User groups → Create group `data-klub-team`, and attach both policies.
6. **Users:** IAM → Users → Create user, one per member, lowercase first name (it becomes their
   S3 folder name). Tick **Provide user access to the console**, **Autogenerated password**, and
   **User must create a new password at next sign-in**. Add the user to `data-klub-team`. Don't
   create access keys.
7. **Send each person** the sign-in link, their user name and the temporary password **in a direct
   message**, never in a channel.

## First sign-in (each member)

1. Sign in with the link, your user name and the temporary password, and choose a new password.
2. Top right, your name → **Security credentials** → **Assign MFA device** (an authenticator app or
   a passkey). Until you do, everything else is blocked.
3. Sign out and back in with MFA.
4. Test: Lambda → Create function `dk-<you>-hello`, Python 3.12, **Use an existing role** →
   `data-klub-team-lambda`. Deploy, Test, and check the log.

## Loading files to Databricks from a Lambda

Databricks Free Edition can't read our S3 bucket, but a Lambda can push files to a Databricks
volume over its REST API:

1. In your Databricks workspace: Settings → Developer → Access tokens → generate a token.
2. In AWS: Systems Manager → Parameter Store → Create parameter
   `/data-klub/<you>/databricks-token`, type **SecureString**, value = the token. Add
   `/data-klub/<you>/databricks-host` (String) with your workspace URL.
3. In your Lambda, read both parameters and upload with
   `PUT https://<host>/api/2.0/fs/files/Volumes/house_prices/raw/landing/<file name>` and the header
   `Authorization: Bearer <token>`.

Never put the token in code, in a Lambda's plain environment variables or in chat.
